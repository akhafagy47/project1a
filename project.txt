CMPUT 350 Project 1b: Galaga
============================

Team: Maulik Srivastava (maulik2), Abdulrahman Khafagy (akhafagy)


Overview
--------
This project continues the 2D game engine from Part 1a and uses it to build a Galaga style
shooter. The engine (engine/) is in the CMPUT350 namespace and knows nothing about Galaga. The
game (galaga/) is built entirely out of engine objects. main.cpp only creates the engine at
768x1024 and adds a single Galaga object; Galaga then creates and removes every other object.

Build: cmake -B build && cmake --build build, then run ./build/Project1.

Controls:
  5             insert a coin
  1             start a game (uses one credit)
  A / Left      move left
  D / Right     move right
  Space         fire (at most two player bullets on screen at once)
  P             pause / unpause (engine debug key)
  N             while paused, advance one frame (engine debug key)


Engine
------
Game loop (GameEngine::Run), once per frame at 30 fps:
  1. Remove dead objects (swap-and-pop, so removal is O(n) and leaves no gaps).
  2. Add and Initialize() objects that were added during the previous frame. New objects wait in
     a pending list, so objects can be added safely from inside any callback.
  3. Process window and keyboard events.
  4. Update() every object.
  5. Process collisions.
  6. LateUpdate() every object.
  7. Render background, then foreground, then UI, then display.
Before every call into an object the engine sets GameContext::CurrObject to that object, so an
object can hand out weak pointers to itself (for example, as a bullet's parent or when registering
for notifications).

Drawing and transforms: objects always draw in their own local space. Before rendering an object,
the engine reads its GetLocation() and GetRotation() and gives them to the screen DrawContext,
which rotates and offsets every drawing command. The GUI DrawContext never applies a transform,
so RenderUI() draws in screen coordinates. DrawContext::ReverseTransform undoes the offset and
applies the transposed (inverse) rotation matrix to convert screen points back to local space.

Collisions: each frame the engine collects all CollisionObjects once and tests each pair exactly
once. Objects that died earlier in the same frame are skipped. A pair is checked in two steps:
  1. The objects' local bounds are transformed to world-space axis-aligned boxes and compared.
  2. Only if the boxes overlap are the individual shapes (lines, circles, axis-aligned rects)
     transformed to world space and compared.
Supported shape tests: line-line, line-circle, line-rect, circle-circle, circle-rect and
rect-rect. Lines are directed. For a line, the engine finds the first point along the line that
touches the other shape (from p1 towards p2), keeps the earliest such point over all of the
object's lines, converts it back to the object's local space, and passes it to
CollisionEnter(obj, point). Pairs of circles and/or rects have no single collision point, so
those objects get CollisionEnter(obj). An object that returns no shapes is treated as a single
rect covering its bounds.

Keyboard: the engine no longer sends key events to every object. Objects register a key's
scancode with a notification string through EngineView::InstallKeyDownNotification /
InstallKeyUpNotification. When that key is pressed or released, the engine sends the string to
the notification manager. Several keys can share one notification (A and Left both send the
"move left" notification).

NotificationManager: maps a message to a list of weak_ptr listeners, so it never keeps an object
alive. Register() ignores duplicates. Unregister() and Notify() also remove listeners whose
objects no longer exist, and an empty list is removed from the map. Notify() delivers
immediately, from a copy of the listener list, so a listener may register or unregister during
ReceiveNotification() without breaking the loop. Weak pointers are compared with owner_before,
which still works after the object has been destroyed.

EngineView iteration: cbegin/cend/begin/end return the engine's internal vector iterators, so
Galaga can loop over all live objects with a range-based for loop.

Bezier: cubic Bezier curves with 4 control points per segment. A path of 3k+1 points has k
segments and is valid for 0 <= t <= k. t is clamped to that range. The static and member versions
of GetPoint/GetSlope share the same code.


Galaga game
-----------
Galaga state flow (Galaga.h/.cpp):

  WaitingForCoin --(1 pressed with credits > 0)--> Startup
  Startup --(about 3 seconds)--> Waves
  Waves --(all 40 enemies spawned and all in formation)--> Playing
  Playing --(every enemy destroyed)--> Startup (next stage)
  Startup / Waves / Playing --(player died, lives left)--> PlayerDown
  PlayerDown --(all enemies back in formation, then "READY" for 2 seconds)--> back to the state
                the game was in when the player died, with a new player
  Startup / Waves / Playing --(player died, no lives left)--> GameOver
  GameOver --(about 5 seconds; every enemy and bullet is removed)--> WaitingForCoin

- WaitingForCoin shows the title, "PRESS 5 TO INSERT COIN", the number of credits and the high
  score. Coins can be inserted at any time.
- Startup shows "STAGE n" and creates the player if there isn't one. The score, high score, lives
  and stage are shown from here on.
- Waves spawns 5 waves of 8 enemies, one wave every 2 seconds, with ships in a wave a few frames
  apart. The formation is 5 rows by 8 columns: row 1 holds Enemy3, rows 2-3 Enemy2 and rows 4-5
  Enemy1. Wave w takes slots w, w+5, w+10, ... (numbered row by row), so every wave includes all
  three enemy types. Even waves enter from the left and odd waves from the right, on a smooth
  two-segment Bezier path that swoops across the lower screen and rises into the slot from below.
  Once all 40 enemies have been spawned and are on the screen, Galaga begins sending enemies that
  have reached the formation to attack (at half the normal rate) while the rest finish entering.
- Playing sends an enemy to attack at a regular interval. The interval starts at 2 seconds and
  gets shorter on later stages (minimum 2/3 of a second). The attacker is chosen
  deterministically through the engine iterator: the k-th live enemy, where
  k = (attack number * 7) mod (number of live enemies), which spreads attackers across the
  formation. An enemy that is not in formation declines the order.
- If the player dies while waves are still spawning, spawning pauses until the player respawns.
- Galaga keeps a weak_ptr to the current Player. It detects the player's death either from a
  "PlayerDied" notification or by noticing that the player is no longer alive.

Score: Galaga registers for each enemy type's "killed" notifications and keeps a table of points
(in formation / out of formation): Enemy1 50 / 100, Enemy2 80 / 160, Enemy3 150 / 400. Each kill
also decrements the count of live enemies. The high score is kept while the program runs.

Enemies (Enemy.h/.cpp): Enemy is an abstract base class that does everything common to all
enemies:
- Follows Bezier paths at a constant speed (6 px/frame). Each path gets an arc-length table of
  100 samples per segment; every frame the enemy advances a fixed distance, finds the matching t
  by binary search and linear interpolation, and faces along the curve's slope.
- Hovers left and right in formation in sync with the global frame counter. Paths into the
  formation aim at where the hovering slot will be when the enemy arrives, so there is no jump at
  the end.
- After an attack, builds a return path that leaves along the current heading and comes into the
  slot from above or below, whichever side the enemy is on. It then turns smoothly back to
  nose-down.
- Fires bullets aimed at the attack target at set points along the attack path.
- Collides only with the player and player bullets. Hits are counted in CollisionEnter() and
  applied in LateUpdate(). When health reaches 0 the enemy sends
  "<Type>KilledInFormation" or "<Type>KilledOutOfFormation" and kills itself.

The three enemy types differ in health, look and attack path:
- Enemy1 (yellow bee, 1 health): dives straight down at the player's x position, leaves the
  bottom of the screen and re-enters from the top before returning to formation.
- Enemy2 (red butterfly, 1 health): zigzags down towards the player in three S-curves.
- Enemy3 (green boss, 2 health, turns magenta when damaged): swoops down and flies one full loop
  around the player.

Player: moves left and right at 8 px/frame, cannot leave the screen and keeps at most two
bullets alive. The player registers in Initialize() for the movement and fire notifications that
Galaga installs. Its bounds and shapes are fixed in local space; it moves only by changing
GetLocation().

Bullets: a player bullet moves up and an enemy bullet moves towards its target. Each bullet uses a
directed line from its previous position to its current one, so a fast bullet cannot skip over a
thin target. On a hit, the bullet stops at the collision point (choosing the largest y if there
are several) and draws a single circle there. Player and enemy bullets are different colors.
Bullets pass through other bullets, enemy bullets ignore enemies, and a bullet is destroyed when
the object that fired it is destroyed.


Important design decisions and changes to the basic API
--------------------------------------------------------
- GetBounds() and GetShapes() are in the object's local space, like drawing. The engine
  transforms them to world space using GetLocation()/GetRotation().
- Notifications arrive without a GameContext, so objects that need the context to react (Galaga
  for StartGame and PlayerDied, enemies for hits) record the event and act on it in their next
  Update() or LateUpdate().
- The key notification names are public constants on Player (Player::kShiftLeftKey,
  kShiftRightKey, kStopLeftKey, kStopRightKey, kFireKey). Galaga uses them when installing the
  keys, so the names exist in only one place.
- Enemy kill notifications are "Enemy1KilledInFormation", "Enemy1KilledOutOfFormation", and the
  same for Enemy2 and Enemy3.
- Bezier::GetMaxT() const: returns the largest valid value of t for a curve, which is the number
  of cubic segments. This was added so enemies can tell when they have reached the end of their
  path.
- Enemy adds IsInFormation() (used by Galaga to choose attackers and to wait for the formation)
  and the protected helpers StartAttack(), SetHealth(), Health(), MaxHealth(), ScreenSize(),
  TypeName() and OnAttackPathFinished(), which the three enemy types build on.
- Galaga's constructor takes the window width and height, as in the provided main.
- Code style follows the repository's .clang-format (Google based, 4-space indent, 100 columns).
  Members use an m prefix, constants a k prefix, and functions are PascalCase.


Extra credit
------------
Vector2D: MathUtil.h defines "using Vector2D = Point2D;". Vector2D is used wherever a value is a
direction, velocity or offset rather than a position:
- Bezier::GetSlope's return type
- the Bullet constructor's heading and the bullet's velocity
- enemy headings, bullet aim directions and the tangent vectors used to build the loop path
- the direction vectors in Line::ClosestPoint / Line::Crosses and in the engine's collision tests
- the offset taken by Rect::operator+ / operator+=
- the offsets added to formation slots in Galaga's entry paths and UI layout
Positions remain Point2D.
